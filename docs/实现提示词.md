## 任务

实现一个**单用户、本地优先的个人知识系统**。它是一个 monorepo，包含 Electron 桌面端、Web 端、Swift iOS 端、以及一个服务端（同时支持腾讯云 CloudBase 和自托管两种部署）。

**先读文档，再动手。** 仓库根目录有三份规格：

| 文档 | 管什么 | 权威范围 |
|---|---|---|
| `docs/产品文档.md` | 做什么。对象模型、视图、提炼、输入、画布、AI、回看 | **产品行为**以它为准 |
| `docs/技术架构.md` | 怎么做。数据表、同步协议、合并规则、搜索、双后端 | **数据结构和技术选型**以它为准 |
| `docs/UIUX设计.md` | 长什么样。设计令牌、分栏、各页面形态、状态、键盘 | **界面和交互**以它为准 |

`design-refs/` 里有参考产品的真机截图和设计令牌，是实现界面时的依据。

**三份文档末尾都有「遗留」章节——那些是未决问题。遇到时提问，不要自己发明答案。**

## 仓库结构

```
drill/
├── apps/
│   ├── desktop/        Electron（渲染层复用 packages/ui）
│   ├── web/            Web（复用 packages/ui，无本地库）
│   └── ios/            Swift（SwiftUI）
├── packages/
│   ├── core/           数据模型、同步客户端、类型定义（TS，desktop/web 共用）
│   ├── ui/             共享组件（React）
│   └── server/         服务端
├── infra/
│   ├── sql/            迁移脚本（单一套，两边共用）
│   ├── docker/         Dockerfile（CloudBase 和自托管共用同一份）
│   └── compose/        docker-compose —— 本地开发就是自托管路径
└── docs/
```

**服务端写 TS。** Electron / Web / 服务端共享 `packages/core` 的类型。Swift 独立，只通过 HTTP 和同步协议交互。

## 不可违反的约束

这几条错了会静默损坏数据或让双后端分叉，**先读完再写代码**：

**1. 合并逻辑只在服务端，且全项目只有一份。**
客户端只做三件事：本地记变更、推、拉。**绝对不要在 Electron 或 Swift 里再实现一遍合并**——两份实现会静默写坏数据。这是选择「服务端合并」的唯一理由。

**2. 资产必须客户端直传对象存储。**
服务端只签发 `storage_key` 和上传凭证。路径必须服务端下发（`{user_id}/{asset_id}`），客户端不能自己拼——否则能伪造路径写到别人目录。云托管请求包体上限 20M，大文件本来也过不去。

**3. 不要用云函数，用云托管（Docker 容器）。**
用云函数会和自托管路径分叉。

**4. 数据库两边都是 PostgreSQL，连库是同一行代码。**
CloudBase 和自托管只差两处：**认证**、**存储凭证的获取方式**。其他都是环境变量。

**5. 本地开发用 docker-compose，它本身就是自托管路径。**
这不是额外工作，是同一个东西。

**6. `kinds` 定义存数据库，不写死在代码里。**
加一个 kind = 插一行 `kinds` + 写一份 `properties`。不改代码、不发版。三个端都从这张表读定义。同理 `sources.properties` 声明连接器产出的字段。

**7. AI 产出必须 `kind = ai_output`，且只能新增。**
AI 可以提议改属性（走 `proposals`），**但不能改任何已有对象的 `title` / `body`**。原文永远是用户写的。生成、扩写、批注一律是新对象 + 引用。

**8. 分组是「区域」，不是「集合」。**
成员是每张画布各自的（`placements.group_id`）。在一张画布上往框里加东西，不影响别的画布。

**9. iOS 只做三件事**：拉取、显示、捕获写进 outbox。
不实现合并、不实现段落编辑、不存版本。

**10. 两个时间必须分开。**
`captured_at`（客户端捕获时刻）和 `created_at`（服务端接收时刻）。**时间轴用 `captured_at`**——否则离线捕获的东西会全堆到上传那一刻。

**11. `body_blocks` 用 block id + 分数索引，不要用数组下标。**
两端在中间各插一段，下标会错位。

**12. 时区必须存。** 「今天/本周/本月」是本地时区概念，服务端算不对就会把晚上 11 点记的东西算进第二天。

**明确不做**：CRDT、端到端加密、客户端合并、全局图、画布的排版功能（对齐/分布/自动布局）、实时协作、第三方 API 开放。

## 实现顺序

**每个里程碑都必须可运行、可自测，不要一次写完再跑。**

**M0 · 底座**
`infra/` 全部 + `packages/server` 的最小可跑版本：Postgres schema、迁移、`/sync/push`、`/sync/pull`、`/assets/sign`、`/assets/commit`、认证抽象（两套实现）。用 docker-compose 起本地环境。**写测试验证合并规则，特别是段落级按 block id 合并。**

**M1 · Electron 最小闭环**
捕获 → 列表 → 提炼 → 同步。本地 SQLite、outbox、离线可用。**界面按 `UIUX设计.md` 的令牌和分栏做，不要先随便糊一个。**
验收：断网捕获三条，恢复网络后能同步，且 `captured_at` 保持正确。

**M2 · 画布**
`placements`、分组、嵌套、防环、导图工具、自由摆放。**只做「拉进来、摆位置、连线」三件事。**

**M3 · 搜索与 AI**
`pg_trgm`（P0）→ `pgvector` + `bge-m3`（P1）。相关、洞察、局部图。**洞察是纯 pull，允许沉默。**

**M4 · 连接器**
`Connector` 接口 + Obsidian / Chrome / Codex 三个实现。**聚合粒度是连接器的责任**——Chrome 必须聚合成「一次浏览会话」，否则会淹掉系统。

**M5 · Web**
复用 `packages/ui`，无本地库，纯在线。

**M6 · iOS**
SwiftUI。只做拉取、显示、捕获入 outbox。**冷启动 < 1 秒**，这是硬指标。

## 工作方式

**第一步不要写代码。** 先做这三件事，等我确认：

1. **读完三份文档，用你自己的话复述一遍核心模型**（对象 / 形态 / 主体与附文 / 属性 / 引用 / 视图）。让我看出你哪里理解错了。
2. **列出你在文档里发现的矛盾和缺口。** 三份文档是分几轮讨论出来的，很可能有对不上的地方——**发现就是功劳，不要自己圆过去。**
3. **提出「遗留」章节里你必须先知道答案才能动手的问题。** 其余的可以按文档里的倾向先做，标注 TODO。

之后每个里程碑开始前，先给我一个**简短的计划**（改哪些文件、加哪些表、怎么验证），我说可以再动手。

**遇到几种情况必须停下来问我，不要猜：**
- 文档之间冲突
- 文档某个地方含糊到有两种合理解释
- 你打算引入文档里没有的依赖或概念
- 你发现某个设计在当前约束下做不到

**不要做的：**
- 不要一次生成几千行然后说「完成了」
- 不要为了让测试通过而放宽约束（比如在客户端加一份合并）
- 不要提前优化（几万条数据不需要分片、不需要微服务）
- 不要重写文档里已经定好的东西，有意见先提
