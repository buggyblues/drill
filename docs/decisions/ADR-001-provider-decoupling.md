# ADR-001：认证、附件存储与运行位置解耦

日期：2026-10-13。状态：已采纳（用户明确要求开源部署可自由选择存储，本人使用 COS）。

## 问题

原 `BACKEND=cloudbase` 同时选择认证和资产适配器；自托管 Compose 又强制启动 MinIO。无法直接表达“自托管应用 + CloudBase 认证 + COS 附件”等组合。

## 决策

- `AUTH_MODE` 只选择认证，`STORAGE_DRIVER` 只选择存储，`DATABASE_URL` 配置数据库；运行位置不决定这些选项。
- S3 驱动共享 MinIO/COS/S3/R2 的协议适配，供应商差异通过配置表达，不进入对象业务逻辑。
- 未显式设置的选项继续使用旧 BACKEND 默认值；新环境文件显式设置两个选项。
- `compose.external.yml` 不依赖本机存储服务。原 `compose.yml` 复用共同服务并附加 MinIO；保留现有项目名和卷名。
- 客户端仍直传对象存储，数据库只记录稳定标识与元数据；本次不改变客户端协议或数据库结构。

## 边界与验收

配置切换不执行数据迁移；已有文件须通过对象 API 复制并校验，保留 storage_key、元数据和用户归属。原存储保留至回退窗口结束。

自动验证四种认证/存储组合、旧默认兼容、签名主机/区域/寻址方式、内外端点分离及 Compose 依赖/卷名。云端 API 返回、CORS、私有权限和媒体预览需要真实供应商验收，不能由本地签名测试代替。
