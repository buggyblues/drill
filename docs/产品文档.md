# 产品文档

## 定位

所有输入进同一个池子。提炼就是给它设属性。属性决定它以后怎么被找到。

---

## 一、核心模型

一切皆对象。

```
对象
  主体    形态决定
  附文    Markdown，可为空
  属性    类型 / 归属 / 标签 / 系列 / 时间
```

**形态**：`text` / `image` / `audio` / `video` / `link` / `canvas`
由输入方式自动决定，不可改。

**主体**

| 形态 | 主体 |
|---|---|
| text | 一段文字 |
| image / audio / video | 文件 |
| link | URL |
| canvas | 一组引用 + 位置 |

**附文**
所有对象都有，一份 Markdown，可为空。主体和附文里的 `[[引用]]`、`#标签` 都解析。
不设「主体放什么、附文放什么」的规则。

**属性**

| | 说明 |
|---|---|
| `kind` | 语义类型，唯一。未设 = 未提炼 |
| `归属` | 它挂在哪个容器下。**是对象之间的一条关系，不是对象上的一个字段** |
| `tags` | 多个，横切 |
| `series` | 单个，可空 |
| 时间 | 捕获 / 创建 / 确认 |

**「归属」和「引用」是同一种东西的两面。** 对象之间只有一张关系表，`归属` 和 `引用` 是它的两种类型。这样项目可以同时属于两个领域（多对多），而列做不到。

**「挂在谁下面」能走多层**：领域 → 项目 → 行动。领域详情页看到的是这个领域里的**全部**东西，不管它挂在哪个项目下。

**`kind` 的集合存数据库，第一版不给 UI 改。** 加一个 kind 是插一行，不用发三个版。

**十一个：**

| 容器 | |
|---|---|
| `领域` | 长期存在的分类，几乎不变 |
| `项目` | 有始有终的容器 |
| `画布` | 空间视图（`form = canvas`） |
| `分组` | 画布上的一块区域 |

| 执行 | |
|---|---|
| `行动` | **无歧义的下一步**，有流转 |
| `产物` | 不可变的产出 |

| 知识 | |
|---|---|
| `沉淀` | 可复用的判断，可升版 |
| `资料` | 外部内容 |
| `想法` | **还没澄清的** |

| 自我 | |
|---|---|
| `自我认知` | 关于你自己的陈述 |

| 不是你写的 | |
|---|---|
| `AI生成` | 洞察、总结、扩写、批注 |

### kind 专属属性（Label）

**每个 kind 可以声明自己的专属属性**，存在 `kinds.properties`。

支持的属性类型：`text` / `number` / `checkbox` / `datetime` / **`label`** / `object`（关联另一个对象）。

**`label` 是其中最要紧的一个**——类型内的固定选项集：

```json
{
  "status": { "type": "label", "options": ["待做", "在做", "阻塞", "完成"] },
  "due_at": { "type": "datetime" }
}
```

**Label 和 Tag 的分工不能混：**

| | Label | Tag |
|---|---|---|
| 范围 | **绑定一个 kind** | 跨所有 kind |
| 选项 | 预设固定 | 自由生长 |
| 例子 | 行动的流转状态 | `#AI`、`#哲学` |

**别用标签表达「类型内的分类」。** 书有 genre「小说」，如果做成 tag，文章和电影也会被打上「小说」——分不清「这是一本小说」和「我在写关于小说的小说」。而且 tag 自由生长，你会写出「小说」「长篇小说」「fiction」三个值。

**声明它的作用是让「kind → 属性 → 界面」自动打通：**

- 属性面板知道该渲染**下拉框**而不是输入框
- 筛选器自动出现**「行动 · 状态」**
- 看板视图自动**按它分列**

**不声明的话，这三件都要在代码里为每个 kind 硬编码——加一个 kind 就要改三个端。**

目前只有两个专属属性：`status`（行动）、`applies_to`（自我认知）。

**`applies_to` 用 Label 机制，选项由 AI 提议新增**——和标签同一条规则：AI 只归一，不凭空创建。

**两组配对：**

- **想法 → 行动**，这是「澄清」这个动作的两端。GTD 的原话：「因为『Mom』是模糊的，它出现在清单上时仍然**触发压力**；『Call Sis…』**触发行动和正向投入**。」
  **所以硬约束是：写「行动」时它必须是一个具体的下一步，否则它就该是「想法」。**
- **沉淀 → 产物**，一个是可复用的判断，一个是不可变的交付。

**`ephemeral`**：白板上的临时文字。不进任何视图、不进搜索、不进时间轴，只活在它所在的那张画布上。要转正手动切。

## 二、关系

只有一种：**引用**。

- 写 `[[X]]` 产生，方向是「这条 → X」
- 也可以在属性面板手动挂
- 反向自动：「被提到」

不设关系类型。两条数据是什么关系，看内容自己判断。

**写 `[[X]]` 而 X 不存在时，参考 Obsidian**：写入时不创建，只渲染成一种更暗的「未解析链接」；**点击它才创建**。这样打错名字不会产生空对象。

**显式与推断分开**：你写的标记直接成为结构；系统从自然语言里猜的只是建议，要你确认。

### 局部图

打开一个对象，能看到它的关联。**只做一跳**（可展开到两跳），而且**两个方向要分开显示**：

- **它引用了谁**
- **谁引用了它**

这两个是不同的信息。

**不做全局图。** Capacities 只有单对象图，明确不做全局的——节点太多看不出东西。整个库的结构由**认知地图**承担（见「回看」那节），它显示的是内容算出来的主题，比"你连过什么"更接近真实。

**图会很稀疏**：对象上万，引用可能只有几千条，大部分对象打开时是空的。**空的时候直接写「这条还没有关联」**，不要画一个孤零零的点。

**比 Capacities 多一层**：你的引用能记住「是从哪一句话发出的」，所以图上的边可以点回原段落。

**第一版只读。** 图上画线的交互成本比看起来高，而你的连线入口已经有三个了（正文里打 `[[`、属性面板挂、画布上画线）。

## 三、分组

**分组是一个对象，成员是它引用的一组对象。**

- **成员无序**——顺序由画布上的摆放决定。不加第二套排序，否则会和画布打架。
- **可以复用到任意画布**——因为它自带成员，拿到哪张画布上都框着同样那组东西。
- **分组名要认真**——缩小时只看得到它。

---

## 四、视图

**视图不只是筛选器。它有三部分：**

```
视图 = 筛选（哪些对象）+ 展示形式（列表 / 画布 / 看板）+ 专属功能（对这些对象做什么）
```

| 视图 | 筛选 | 专属功能 |
|---|---|---|
| 新增 | 时间（今天 / 本周 / 本月） | 提炼 |
| 行动 | `kind = 行动` | **流转** |
| 个人记忆 | `kind = 自我认知` | 待定 |
| 领域 | `归属`（含下层的项目） | — |
| 时间轴 | 时间 | — |
| 相关 | 相似度 | — |

**未来还会有更多这种视图。** 每加一种，就是「某个属性集合 + 为它们定制的操作」。

---

## 五、提炼

**提炼是主动进入的一个动作，不是队列。**

- **「新增」是时间筛选**（今天 / 本周 / 本月），不是一个待办队列
- **没有计数，没有提醒，没有强制**
- 你想提炼的时候，从列表或画布上主动去看，想提炼什么就提炼什么

**收件箱这个概念取消。** 三个月前拉进来一直没提炼的对象不会出现——它只能在时间轴、搜索、或它所属的领域/画布上找到。它本来就不是新的了。

右侧是提炼面板。AI 提议，你确认。

**AI 的建议保留成记录**（`proposals`），以后能看到「它建议什么、我改成什么」。

## 六、输入

**操作方式和展示形式是两个正交的维度：**

```
操作方式：快捷键小窗 / 拖文件 / 粘贴 / 录音 / …
展示形式：列表 / 画布 / …
```

**每种展示形式里都有新建入口。**

**一个可选捷径**：已经知道类型时，可以直接写 `/类型/对象名/`（Capacities 的做法，例 `/media/Forrest Gump/`）。**默认路径仍然是不选类型**——这只是给已经想清楚的人省一步。

### 连接器

外部源：Codex 会话 / Obsidian 笔记 / Chrome 记录 / …

连接器默认折叠，显示新增数量。**展开即视为看过**——锚点前移，UI 上不再高亮。

**「看过」只记录看过，不代表需要任何操作。**

**聚合粒度是连接器的责任。** Chrome 不能一次访问一个条目（11,680 条会淹掉系统），必须自己聚合成「一次浏览会话」。

**外部内容进来是普通对象，但正文是冻结快照**：

- 外部语法（`[[ ]]`、`(( ))`）降级成纯文本，不产生关系
- 同名对象存在时，提炼时**提议**建立引用
- 外部源更新不自动同步，只标记「有一版新的」
- 连接器只读，不回写

原则：**外部内容在边界上被翻译成你的模型，不是让你的模型去兼容它。**

### 不同来源的展示

连接器产出的对象带专属字段（小红书有点赞数、Twitter 有转发数）。

**这些字段的 schema 声明在 source 上**（和 kind 的专属属性同一套机制），值存在 `extra`。界面读 schema 渲染，并按 `connector` 选卡片组件。

**加一个新平台 = 插一行 + 一份字段声明。不加 kind、不改代码。**

这是因为你把「形态」和「语义」分开了。Capacities 把 Tweet 做成一个**类型**，所以每加一个平台就要加一个类型——**它只能说「这条关于什么」，说不了「这条是什么」。**

## 七、画布

**画布是一个视图，不是容器。** 同一个对象能出现在任意多张画布上，位置存在画布那一侧。

**画布可以有属性**——它属于哪个领域、哪个项目，和其他对象一样。

### 可以嵌套

一张画布可以放到另一张画布上。进入时区分：

- **展开**（在原位显示内容）
- **进入**（切换上下文，有面包屑）

**防环**：写入前从目标画布向上遍历，遇到要放入的对象就拒绝。

### 三条来自 Heptabase 的经验

**一、白板不是起点，是第二站。** 官方原话：只在「已有资料且脑中已有粗略理解」时才开白板，新主题先放**一张**笔记卡。

**所以输入需要两种展示形式**——列表用来倒想法，画布用来整理理解。一开始就在画布上写会卡住，因为画布要求你先有结构。

**二、不要滥用双向链接。** 官方原话：「过度使用会让真正重要的连结无法凸显，造成反效果」。

→ **图视图默认只显示被引用次数超过阈值的**，其余靠搜索。

**三、呈现能力主动降级。** 它的白板早期刻意不做手写、形状、线条，先把力气放在「卡的复用、双向链接、白板层级」上。

→ **自由摆放只做三件事**：拉进来、摆位置、连线。

### 画布上的工具

- **导图** —— `Tab` 长子节点、`Enter` 出兄弟节点，位置自动算，父子关系自动成为引用
- **自由摆放** —— 拖位置，手动画线，一条线就是一条引用

两个工具可以在同一张画布上混用。

### 显示选项

主体和附文怎么显示**由用户选**：只显示主体 / 折叠附文 / 都显示。

默认跟随全局，单个 placement 可以覆盖。

## 八、AI

**只有两个动作，一个便宜一个贵。**

| | 用什么 | 什么时候出 |
|---|---|---|
| **相关** | 向量，便宜 | **秒出**，3–5 条，不打扰 |
| **洞察** | LLM，贵 | **点了才跑** |

### 洞察是纯取用式的

**不做任何定时或自动出现。没有推送，没有红点。**

**允许沉默。** 证据不足就降级，没有明显张力就什么都不说。这条是它敢长期开着的前提。

**注意 Proposal 和 `AI生成` 是两种东西**：Proposal 是「AI 建议的**字段值**」（存在 `proposals` 表），`AI生成` 是「AI 产出的**内容**」（是一个对象）。前者是判断记录，后者是内容。

### 所有 AI 产出都是 `AI生成` 对象

**不禁止落库，但必须打上 `kind = AI生成`。**

这比「不落库」好在三点：能回看 AI 说过什么；时间轴按 kind 过滤掉它，所以「真实」没被破坏；符合「一切皆对象」，不用开例外。

> flomo 的做法是禁止保存（「洞察报告不等于你的思考，一键存进产品会污染语料」）。但它的模型里没有 kind，所以只能靠「不许存」来解决。**你的模型有这个工具，就不需要那个限制。**

**生成和扩写可以做**，它和批注是同一种东西：

| AI 能做什么 | 怎么做 |
|---|---|
| **提议改属性** | 走 Proposal，你确认后才写 |
| **生成 / 扩写 / 批注** | **新开一个 `AI生成` 对象，引用原对象** |

**一条硬边界：AI 可以提议改属性，但不能改主体和附文。**

原文永远是你写的，「必要难度」那条原则就保住了。

批注在数据上就是一条引用（`AI生成 对象 → 引用 → 原对象`）。原对象的详情页反查，就能列出「有哪些 AI 批注」。

### 「不是你写的」是一整类

```
你写的       沉淀 / 想法 / 行动 / 产物 / 领域 / 项目 …
不是你写的   资料（来自外部） / AI生成（来自 AI）
```

**这一整类适用同一条规则：都不能直接变成「沉淀」。要升格，你必须用自己的话重写一遍。**

### 入口必须在必经路径上

flomo 上线后收到最多的反馈是「这个功能到底在哪」。**纯 pull 的唯一代价是发现性，补的是入口位置，不是通知。**

所以：对象详情里有「相关」和「洞察」；左侧栏另有一个入口（选范围：最近 7 天 / 某领域 / 某画布）。

### 标签：AI 只归一，不凭空创建

**AI 只提议合并和归一已有标签，不创建新标签。**

### 验收标准：思考占比 ≥ 80%

少楠讲他自己怎么用 AI：

> 让 AI **挑战我，然后我再挑战它**……之后我一定要手工修改。修改完之后，再和它思辨。
> **我的思考占比大概 80%。如果只有 10%~20%，我丢出去的东西可能有点心虚。**
> **AI 重点不是提效，而是提质。**

**「思考占比」比任何指标都适合当你的验收标准。** 提炼面板应该能回答：这一条里，AI 给的和你想的，各占多少？

**推论：AI 不该让你爽。** 官方原话是「AI 是一个思维伙伴，它就不能让你爽，**它一定会反驳你**」。

所以洞察要输出**思维盲点**和**问题**，不只是「你这两条很像」。

**发现重复是回顾，指出盲点是质问。**

## 九、界面

```
┌───────────┬──────────────────────────┬──────────────┐
│ 新增      │  今天  本周  本月         │              │
│ 行动      │  🔍                      │   提炼 /      │
│ ───────── │                          │   相关 /      │
│ 领域      │                          │   洞察        │
│  自媒体    │        画布 / 列表        │              │
│  英语      │                          │  （和中间     │
│  设计      │                          │   一样大）     │
│ ───────── │                          │              │
│ 画布      │                          │              │
│  封面这件事│                          │              │
└───────────┴──────────────────────────┴──────────────┘
```

左栏是筛选列表。点任一项，中间按它显示。

**右栏不是只有一个功能**——有候选时是提炼，没有候选时是当前对象的上下文（相关、洞察）。这来自 Heptabase 的右栏用法：素材在右、正文在左，交叉比对。

顶栏只有搜索和 `+`。`+` 是投入一份东西，**不是新建节点**——你在应用里永远不选类型。

**移动端冷启动 < 1 秒。** 超过 1 秒，捕获就退化成「回头再说」，然后就是不做了。

## 十、个人记忆

**它就是一个 kind（`自我认知`），和行动一样有专属视图。**

- 关于你自己的判断，和关于世界的知识**逻辑上分开**：前者的注入策略是常驻，后者是按需检索
- 物理上同一张表，靠 `kind` 区分
- 一条陈述如果两方面都是，**拆成两条**——这是一卡一概念的要求

**每条必须能回答「适用范围」**，这和归属不是一回事：

| | 回答 |
|---|---|
| `归属` | 它属于哪个领域 |
| `applies_to` 适用范围 | 它在**什么情况下**成立 |

「我需要的是方法论，不是软件」——归属可能是某个领域，但适用范围是「在工具选择上」。

**归属是多对多，适用范围是单选列表**——这是两个不同的维度，不要合并成一个控件。

适用范围是研究里唯一被明确列为必需、而原来表里没有的字段。

**区分「编辑」和「推翻」**：

| | 怎么做 |
|---|---|
| 改错字、补说明 | 原地改，版本记快照 |
| **改主意** | **新对象 + 旧对象标失效**，`supersedes_id` 指过去 |

**更新一律 supersede，禁止原地覆盖。而且必须手动，不能自动**——Graphiti 做了自动失效，自建审计发现 **70% 被失效的事实仍然为真**。

## 十一、回看

时间入口：今天 / 本周 / 本月 / 自定义区间。同一张画布换时间窗，不是另一个页面。

跨时间的整体用**高亮**表示范围内创建或修改的内容，其余压暗、折叠成一行。

**回看要尽量被动。** 你能随时看，成本为零；有东西被重新提及时告诉你一声。**不做「今天该回看了」这类提醒**——那会把回看变成任务，而任务会停。

### 三个发现功能，一个出口

上面那些全是**有目的地找**。但你的核心病是「反复回到同一个判断而不自知」——**那个病不是搜出来的，是撞见的。**

**三个都做。** 它们发现的东西不同：

| | 形态 | 发现 |
|---|---|---|
| **认知地图** | 一个视图：全库或某个范围聚成山峰 | **哪几座山你一直在爬** |
| **AI 洞察** | 点一下，读一组，说出张力 | **重复和盲点** |
| **随机漫步** | 一个入口：沿关联走一条路径 | **偶遇** |

**它们共用同一套基础设施**——都需要向量索引（见技术架构第十一节 P1）。所以不是三份工作，是一个底座上的三个消费者。

**认知地图解决「反复」，随机漫步解决「没想到要搜」。** 研究员的判断是前者更对症（「反复而不自知」本质是主题识别问题，不是抽样遇见问题）；但后者能撞见前者结构上抓不到的东西——**所以两个都要，不是二选一。**

**随机漫步不是均匀随机。** 官方机制里，多数步由语义关联引导，**偶尔插入一次「弱相关性的大跨越」**来打破回音室——「弱相关」是它的官方术语。形态是一条接一条的路径，不是抽 N 条并列。**不能指定起点、不保留历史**，这是刻意的。

它 2021 年上线过、因「实际使用率极低」下线，2024 年回归。回归时改了三处：embedding 让「弱相关」可计算、形态从抽签变成有始有终的漫游、从孤立功能变成功能矩阵的一员。

**三条要抄的：**

- **最近看过要降权** —— Readwise 的做法：被展示过后再次出现的概率显著降低
- **必须有「别再给我看这个」** —— Google Photos 曾推逝者和分手照，之后才补负向控制
- **三者必须共用一个出口**（见下）

### 出口才是解决你问题的那一步

> **把「认出来」这个动作本身记下来**——例如标记「**这和我 65 天前是同一个问题**」。

你的九个问题跨 65 天没被认出来，**不是因为没机会遇见，是因为遇见了也没有一个动作把它标出来**。所有回顾类功能最后都变成「看一眼就过去了」，就是因为没有出口。

### 全部只能主动开启

**不能形成仪式时不要推送。**

flomo 的内部分工也是这个：**确定性的走推送，随机的只能主动开启。**

对象可编辑，**保留版本**。回看默认显示当前版，带「改过 3 次」的标记。

## 十二、判断新功能的尺子

> **是否符合「把复杂事物拆解以获得深度理解」。**

Heptabase 用它砍掉了日历集成、时间追踪、炫目可视化——「那些属于专门工具」。

**你的「对齐分布」「仪表盘」「运行记录」用这把尺子都过不了。**

另外两把，来自 flomo：

> 作为知识工作者，**你的工作成果就是决策**。（《输出不是写作》）

**一条沉淀如果不能改变你下次的决定，它就还是分析。** 你的复盘系统产出了 462 条结论句和 146 条 ADR——几乎全是分析，没有决策。这是「做了这么多还是很乱」的直接原因。

> **如果一个功能只有 1% 的用户在使用，哪怕这些用户都付费，我们也可能考虑取消它。**
> 核心是**不做什么**，而不是做什么。我毙过的功能肯定有 100 个了。

**第三把是刹车：**

> 拒绝做完美的产品……**尽量少地去设计**……尽量少的颜色，尽量少的个性……**尽量少的有 ego**。我们只做好一个安静的容器。

这条和你的定位是相反的（你有类型系统、有流转、有提炼流程，你是有主张的产品）。但它精确地标出了你的风险：**你六个月里做的东西，从来不是因为设计得太少。**

## 十三、不做

- **不做 API** —— 数据模型还在迭代，过早开放会带来破坏性变更和攻击面（Heptabase 的判断）
- 不做实时协作、多人共享
- 画布的排版功能：对齐、分布、自动布局、模板、连线样式
- 手写、形状、线条
- 账号、同步、Android
- 富文本编辑器
- 自动分类（AI 只建议）
- 按关系类型筛选
- 「今天该回看了」这类提醒
- 一键保存洞察报告
- 端到端加密
- **不做一键收藏 / 自动导入** —— 同上：「囤得文章越多，人越记不住，**文章不是你的思考**」
- **不做分享、签到这类激励** —— 「扭曲用户的动机」
- **不做「让你选输入方式」的界面** —— 「我特别讨厌产品一上来给用户三个输入按钮……这是把困难丢给用户，是一种**责任推卸**」
  **注意这条和多操作方式不冲突**：快捷键是隐式的，三个按钮是显式的。**支持多种方式，但不做成按钮摆在面前。**

## 十四、连接器的一条约束

来自 flomo 的「**必要难度**」：**存入越吃力，提取越方便。**

你的连接器会拉进大量外部内容。它和「囤积」的区别必须明确：

> **拉进来的是证据（你做过什么），不是素材（别人写了什么）。**

推论：**连接器拉来的内容不算「你写的」，不能直接变成 `沉淀`。** 必须你用自己的话重写一遍才升格。

## 十五、遗留

```
1. 个人记忆的专属视图长什么样（数据结构已完备）
2. 相似度阈值 0.8 是估的，需要在真实语料上标定
   标定方法：拿已知的重复对跑一遍，看漏报和误报
3. 引用的「精选」机制，等做图视图时细化
4. 回溯的负向控制（隐藏某人 / 某时段 / 少看这类）
5. 随机漫步「弱相关大跨越」的具体比例
```

### 已确定：分组是「区域」

**分组不跨画布。** 成员是每张画布各自的摆放，复用的只是容器本身（名字、颜色）。

理由：分组的本质是组织行为，回答的是「**在这张画布上**，这几个东西是一组的」——本来就是局部的。跨画布复用的价值很小，带来的困惑很大。Heptabase 的 Section 也不能跨白板。

**如果你需要跨画布的「一组东西」，不该用分组**——用一个对象引用那一组即可。

**用数据表达集合，用分组表达布局。**
